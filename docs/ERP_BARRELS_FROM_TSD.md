# Шаблон ТЗ: факт бочек/еврокубов из TotalMark Honest → 1С:ERP

Обезличенный шаблон для подрядчика 1С. Подставьте свои организацию, склады, учётные данные TotalMark и имена подразделений ERP.

**Задача:** в конце каждой смены получить из TotalMark количество отсканированной крупной тары по номенклатуре за смену и оформить выпуск в ERP (например, «Производство без заказа»).

**Не входит (типично):** линии с DataMatrix на оборудовании (канистры/бутылка) — у них свой контур агрегации.

---

## 1. Подключение

| Параметр | Значение |
|----------|----------|
| Адрес | `https://tm.totalmark.pro/<TENANT>/hs/Honest/` |
| Авторизация | HTTP Basic (учётка с доступом к **Honest**, не только к `api`) |
| Content-Type | `application/json;charset=utf-8` |

Конкретные логин/пароль/tenant — в защищённом приложении к договору, не в git.

---

## 2. Методы API

См. полное описание: [TSD_HONEST_API.md](TSD_HONEST_API.md).

Кратко:

1. `POST …/jobs/shipment` + Organization/Warehouse → открытые задания.
2. `POST …/job/shipment/info` + Id → `Items[]` с `GTIN`, `QuantityPlan`, `QuantityFact`.

Закрытое задание из списка пропадает — архива нет.

---

## 3. Соответствие складов

| TotalMark | ERP |
|-----------|-----|
| Organization `<UUID>` | Ваша организация |
| Warehouse `<UUID>` | Подразделение / склад сдачи готовой продукции |

Подразделения в API нет — храните соответствие в настройках ERP.

---

## 4. Какие данные учитывать

Все пункты обязательны — защита от ошибок операторов.

### 4.1. Производственные задания

Comment начинается с кириллической **«П»**.

### 4.2. Дата задания = смена

Дата в хвосте Comment `DD/MM`. Смены: 08:00–20:00 / 20:00–08:00 (или ваши). Ночь — оба календарных дня.

### 4.3. Крупная тара

Порог (настройка, обычно > 45 кг/л). «канистр» → исключить. «бочк»/«еврокуб»/размер N кг|л / `(N)` в Comment → учесть.

### 4.4. Потолок

`min(QuantityFact, QuantityPlan)` при Plan > 0. Plan здесь — план **задания TotalMark**.

### 4.5. Номенклатура

Сопоставление по GTIN. Нет в ERP → журнал ошибок, строка не в документ.

---

## 5. Расчёт выпуска за смену

`QuantityFact` накопительный. Нужны:

1. Регистр последнего факта по ключу `(JobId, GTIN)`.
2. Фоновый опрос каждые N минут (рекомендуется 1–5).
3. Закрытие смены (08:00 / 20:00):  
   `Выпуск = ПоследнийФакт − ФактНаНачалоСмены` (только > 0, прошедший фильтры).  
   Затем для всех ключей `ФактНаНачалоСмены = ПоследнийФакт`; закрытые ключи удалить.

Повторный запуск за ту же смену не должен дублировать документ.

Псевдокод — в [TSD_HONEST_API.md](TSD_HONEST_API.md) и в reference-коде монитора (`app.py`, блок TSD).

---

## 6. Сравнение с планом ERP (опционально)

Excel-план цеха и план задания TotalMark — разные вещи. Сравнение факта смены с документами «План производства» ERP — на усмотрение подрядчика (отбор по дате, подразделению, утверждённым планам, номенклатуре крупной тары).

---

## 7. Критерии приёмки

1. Выпуск за смену = прирост capped-факта по заданиям «П» с датой смены.
2. Задание, закрытое среди смены, учтено (за счёт фона).
3. Без «П» / без даты / чужая дата / канистры — не в результате.
4. Ночная смена учитывает оба дня.
5. Идемпотентность закрытия смены.

---

## 8. Ответы на частые вопросы подрядчика

1. **Период в jobs/shipment** — параметра нет; только открытые.
2. **Подразделение** — из таблицы соответствий, не из API.
3. **Отрицательная дельта** — в прирост смены не включать; мастер правит документ.
4. **Одна пара Org/Wh** обычно достаточна для склада бочек.
